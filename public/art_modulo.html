ART Modulo

A goal pool (± arithmetic / % modulo) now frames every state. Under the arithmetic goal, hubs compute A ± B in one shot and the next operator is nothing (∅ — an empty op pool). Under the modulo goal, the operator pool's check (?) and done (✓) nodes drive the recurrence. Hubs map a state (op, A, B) to the next step (op′, A′, B′) of modulo-by-repeated-subtraction, now fully factored: check only compares (emitting an outcome state > or <), separate trained transitions carry the decision (> → sub, < → done), and subtraction itself is always the arithmetic facts' job. Modulo memories are pure control (they output only the next op; operands persist), arithmetic memories are pure facts (only operands; the goal's policy fills silent control). Recall is fed back into the input, so the network runs the algorithm. Trained on every A mod B step for A 0–9, B ∈ {1, 2, 4, 5} — mod 3 is never taught. Note the 19-unit A pool makes digit flips cheap (similarity 0.965), so vigilance must sit above that to keep exemplar hubs.

What this tests

The training set never says what a state is "worth" — each hub only memorizes one transition. Chaining recalls through the input is what turns a lookup table into a running algorithm: mod 5 works because every intermediate state on its trajectory was trained.

Probing mod 3 asks whether transitions can extrapolate. With localist B units the state (Sub, 7, 3) ties every hub (Sub, 7, B′) equally — the blended next-state votes mix A−1, A−2, A−4 and A−5, and the trajectory derails on the first step. Same flat-tie failure as the addition page, now compounding across the recurrence.
